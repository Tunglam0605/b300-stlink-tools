# B300 ST-Link Tools v0.17.0

## Keil/STM-Studio-style Debug Workbench

- Replaces the production Interactive Debug dashboard with a dockable desktop-IDE workbench built on `QMainWindow` + `QDockWidget`.
- Source is the central workspace; Symbols/Call Stack dock on the left; Watch/CPU Registers/Peripherals dock on the right; Breakpoints/Memory/Console/Technical Log/Fault/FreeRTOS/Target tools dock below.
- Debug panes can be moved, hidden, tabified and restored with **Window → Reset Debug Layout**.
- The workstation layout is persisted locally and a corrupt/stale saved layout falls back to the safe default.

## Watch 1: recursive structured variables

- Adds a Keil-style **Watch 1** surface with `Name | Value | Type` as the default columns.
- Global/local expressions such as `xAgvInfor` use GDB/MI variable objects and expand structs, unions and arrays lazily with `-var-list-children`.
- Nested structs/arrays can be expanded recursively for multiple levels instead of stopping at the root object.
- Enum symbolic values are preserved when GDB reports them.
- Child insertion no longer resets the complete tree, so expanding one structure does not collapse unrelated branches.
- Expanded paths are preserved across HALT/step/snapshot refresh where the corresponding variable-object path still exists.
- Value editing remains available only while Interactive Debug is connected and the MCU is HALTED.
- LOCAL and CLIENT use the same structured GDB/MI backend; there is no separate remote Watch implementation.

## Target-aware inspection retained

- Keeps v0.16 STM32F407ZE Target Description, CMSIS-SVD Peripheral Inspector, DWARF type/source service, FreeRTOS Task Inspector and Cortex-M fault analysis.
- The real Peripherals, FreeRTOS, Fault and Target panes are mounted into the new dockable workbench rather than placeholder pages.

## Native C++17 debug data-plane

- Adds the optional `b300_debug_core` C++17 data-plane with bounded sample/event buffers, explicit drop accounting, transport-neutral trace events, a decoder contract and bounded trace pipeline.
- Adds a synthetic throughput gate of at least 50k events/s with zero unexpected drops.
- Adds the `_b300_debug_core` pybind11 ABI v1 module and `NativeDebugCoreAdapter` with `auto`, `off` and `on` modes.
- Python remains the fallback and safety/control plane; native and Python fixed-width decoding paths are covered by parity tests.
- Release packaging can embed the architecture-matched native `.pyd`/`.so`, and the packaged GUI exposes `--native-core-selftest` so CI verifies the actual frozen executable loads ABI v1.
- Real SWO/ITM transport and production hardware trace capture are intentionally not claimed by v0.17.0; that work remains isolated from this release until its parser/transport/hardware gates are complete.

## Realtime and safety boundaries

- Zero-halt Live Monitor remains owned by the normal Debug Studio and is never reparented into the HALT-capable Interactive Workbench.
- Interactive Debug can halt/reset/step the target; Live Monitor remains the recommended path while robot realtime execution must continue.
- Flash/OTA/Bootloader/metadata/Option Bytes policy is unchanged.
- Normal programming still protects Bootloader Sector 0–2 and does not introduce mass erase or arbitrary RDP operations.
- GDB/TCL normal integrated endpoints remain loopback-only, and target-state restoration / HardwareSession ownership remain unchanged.
