# B300 ST-Link Tools v0.15.0

v0.15.0 turns the Debug workspace into a compact engineering debugger while keeping the existing B300 flash/OTA/Bootloader safety boundaries unchanged.

## Engineering Debug Workstation

- Added a mode-first Debug entry: choose `LOCAL`, `GATEWAY`, or `CLIENT` before configuration.
- Rebuilt the Debug Studio around dense engineering panes instead of long setup cards: Symbols, Source, Locals/Watch, Call Stack, Breakpoints, Registers, Live, Memory, Console, and Technical Log.
- Added structured source navigation from AXF/ELF symbols, including function/data browsing and file:line resolution with disassembly fallback when source is unavailable.
- Added coherent HALT snapshots so Source, Stack, Locals, Registers, PC, and Breakpoints are refreshed from one debugger state instead of independent text dumps.
- Added expandable GDB/MI variable objects for structs/arrays, lazy child loading, changed-value tracking, and HALT-only variable assignment with readback.
- Added persistent breakpoint/watchpoint management, enable/disable/delete operations, hardware BP/WP usage counters, and Step Out.
- Added a read-only, HALT-only Memory pane. v0.15.0 does not add arbitrary debugger memory writes.
- Preserved zero-halt Live Monitor behavior; Live remains read-only and does not require Interactive Debug to halt the MCU.

## One-login Client SSH

- Replaced the normal GUI Client path that spawned password-interactive `ssh.exe` consoles with an embedded reusable SSH session.
- Client login is now one place: Gateway host, user, password, SSH port, and `Remember on this PC`.
- The authenticated SSH session is reused by GDB, Safe TCL, and Client Live Monitor, so switching between Live and Interactive Debug does not request the password again.
- No normal v0.15 GUI Client flow opens a CMD/PowerShell window for SSH authentication.
- Host/user/port remain normal profile data; password text is never written to the profile, logs, process arguments, or status messages.
- Remembered credentials are stored only on the local workstation in encrypted-at-rest form. For this internal engineering tool, the local OS account remains the trust boundary.
- GDB/TCL forwards remain loopback-only on both Client and Gateway sides; v0.15.0 does not expose debug ports directly to the LAN.

## Backend debugger API

- Added a non-Qt `DebugWorkstationController` facade so the GUI no longer needs to own raw SSH, GDB/MI, TCL, or ELF parsing logic.
- Added reusable `RemoteSession`, reconnect/keepalive/health reporting, shared local forwards, and explicit disconnect/forget-password lifecycle.
- Added structured APIs for stack frames, locals, variable children, variable assignment, registers, breakpoints/watchpoints, source locations, symbols, snapshots, and memory reads.
- Added Client AXF/ELF verification over the existing shared SSH/TCL session before attaching GDB.
- Kept legacy CLI/SSH tunnel paths for compatibility; they are not the normal v0.15 desktop Client path.

## Safety boundaries preserved

- Normal Application provisioning still never erases/programs Bootloader Sector 0-2.
- Sector 3 metadata and Sector 4-7 Application policy is unchanged.
- No mass erase, RDP change, arbitrary Option-Byte write, or raw debugger memory-write control was added.
- Safe TCL remains allow-listed and Live Monitor remains non-halting.
- Interactive Debug still warns by behavior: Run/Halt/Reset/Step operations can stop the MCU, while Live Monitor is the non-invasive path.
- Debug/Live/Flash/Factory continue to respect exclusive ST-Link hardware ownership.
