# B300 ST-Link Tools v0.16.0

## Target-aware engineering Debug

- Adds an explicit STM32F407ZE Target Description with Flash, SRAM/CCM, peripheral and Cortex PPB regions plus DWT/FPU/NVIC/SCB/SVD/SWO/ITM capabilities.
- Adds a CMSIS-SVD Peripheral Inspector. Register access is lazy, read-only and requires a HALTED target; there is no peripheral write API.
- Adds offline DWARF type/source introspection for verified ELF/AXF images using pyelftools.
- Adds a DWARF-driven FreeRTOS Task Inspector. TCB/List offsets, sizes and ready-list count are derived from firmware DWARF instead of hard-coded kernel offsets.
- Adds Cortex-M Fault Analysis for CFSR/HFSR/DFSR/AFSR/BFAR/MMFAR/SHCSR, MSP/PSP exception-frame reconstruction and source mapping for the captured fault PC when DWARF is present.
- Engineering Workstation gains TARGET, PERIPHERALS, FREERTOS and FAULT tabs.

## Interactive Debug lifecycle

- Includes the v0.15.2 lifecycle correction: Interactive Debug no longer reparents the normal zero-halt realtime monitor.
- Disconnect returns to the normal Studio with Live Monitor still present and usable.

## Safety boundaries

- Flash/OTA/Bootloader/metadata/Option Bytes policy is unchanged.
- Normal flows still protect Sector 0–2 and never use mass erase or arbitrary RDP changes.
- GDB/TCL remain loopback-only for normal integrated Debug.
- Peripheral, RTOS and Fault target access is read-only and HALT-only.
- Zero-halt Live Monitor remains a separate realtime path and is not mixed with HALT-capable Interactive Debug.

## Native C++ roadmap

The C++17 `b300_debug_core` continues on the separate v0.17 development stream. v0.16.0 does not enable native code in production; Python/PySide6 remains the control plane and safety owner until native parity, performance and packaging gates are complete.
