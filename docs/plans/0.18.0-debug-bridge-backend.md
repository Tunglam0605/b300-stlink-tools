# v0.18.0 Backend Plan — B300 as Programmer + Gateway + VS Code Debug Bridge

## Decision

B300 is not an IDE. B300 owns ST-Link safety, OpenOCD lifecycle, remote gateway/session management, VS Code/Cortex-Debug workspace generation, and later remote programming. VS Code owns source-level interactive debugging UX.

## Roles

- LOCAL: this machine owns ST-Link/OpenOCD; VS Code connects to loopback GDB.
- GATEWAY: this machine owns ST-Link/OpenOCD and accepts authenticated remote control/transfer; OpenOCD remains loopback-only.
- CLIENT: no ST-Link required; B300 establishes authenticated SSH control/tunnel and prepares VS Code to attach through a local forwarded GDB endpoint.

## Backend ownership

### Keep and reuse
- `b300_core/openocd.py`
- `b300_core/hardware_session.py`
- `b300_core/remote_session.py`
- `b300_core/ssh_debug_tunnel.py`
- `b300_core/remote_vscode.py`
- existing flash/provisioning safety stack

### New orchestration boundary
Introduce a thin Debug Bridge service that coordinates existing components without proxying GDB traffic.

Responsibilities:
1. validate role and target,
2. acquire/release HardwareSession when local ST-Link is owned,
3. start/stop OpenOCD with loopback-only GDB/TCL,
4. create/reuse SSH GDB forwarding for CLIENT,
5. produce Cortex-Debug configuration for LOCAL and CLIENT,
6. report endpoints/readiness to GUI/CLI,
7. never implement source editor, breakpoint engine, register tree, call stack, disassembly, SVD IDE, or GDB-MI presentation.

## Data-plane rule

B300 controls setup/lifecycle only. Once ready:

- LOCAL: VS Code -> GDB -> OpenOCD -> ST-Link -> STM32
- CLIENT: VS Code -> local SSH-forwarded GDB port -> Gateway OpenOCD -> ST-Link -> STM32

B300 must not proxy individual GDB packets in Python.

## Remote programming extension

Remote flash is different from debug and MUST execute through the Gateway safety boundary.

Future flow:

Client firmware file -> authenticated transfer -> Gateway staging -> SHA-256 -> image/address validation -> target validation -> flash policy -> HardwareSession -> ST-Link -> readback/verify -> result manifest.

Initial allowed remote operation:
- FLASH_APPLICATION

Privileged/disabled by default:
- FLASH_BOOTLOADER
- OPTION_BYTES
- WRP/RDP changes
- FULL_ERASE

Application image requests must reject any payload that writes outside the allowed application flash region or overlaps protected bootloader/metadata regions.

## Safety invariants

- OpenOCD GDB/TCL remain bound to `127.0.0.1` on Gateway.
- Remote debug uses SSH forwarding; do not expose 3333/6666 directly to LAN/Internet.
- Normal application programming preserves Bootloader Sector 0-2 and metadata policy.
- Debug start may halt/reset MCU only after explicit user action in VS Code/debug attach workflow.
- Zero-halt Live Monitor remains a separate mode and must not be conflated with interactive debugging.

## Parallel work boundary

Backend branch owns:
- `b300_core/**`
- `b300_cli/**`
- backend-focused tests
- architecture docs

Frontend/Antigravity branch owns:
- `b300_gui/**`
- frontend UX tests
- UI docs/assets

Frontend must consume backend APIs rather than reimplement OpenOCD/SSH/GDB logic.
