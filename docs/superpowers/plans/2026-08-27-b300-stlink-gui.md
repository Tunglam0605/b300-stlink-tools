# B300 ST-Link GUI Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Deliver one safe B300 F407 provisioning core shared by the existing CLI and a PySide6 GUI, plus reproducible Windows and Ubuntu packages.

**Architecture:** Move validation, OpenOCD orchestration, probe discovery, flash policy, memory reading and metadata decoding into a UI-independent `b300_core` package. Keep `b300_stlink.py` as a backward-compatible adapter and make `b300_gui` call the same services from worker threads. Package both entry points with pinned dependencies and the existing pinned OpenOCD bundle.

**Tech Stack:** Python 3.9+, standard library, PySide6 6.10.3, unittest, PyInstaller, OpenOCD xPack 0.12.0-7.

**Spec:** `docs/superpowers/specs/2026-08-27-b300-stlink-gui-design.md`

## Global Constraints

- Target is STM32F407 Main Board B300 only.
- Sector 0–2 (`0x08000000..0x0800BFFF`) is always read-only.
- Sector 3 (`0x0800C000..0x0800FFFF`) changes only in the standard provisioning transaction.
- Intel HEX data is allowed only in Sector 4–7 (`0x08010000..0x0807FFFF`).
- Marker `0x53544C4B` is written only after OpenOCD reports successful program and verify.
- No mass erase, Option Bytes/WRP write, hidden retry, COM selector, UART OTA or GUI debug.
- Every target halt used for inspection is followed by resume before disconnect.
- CLI command names and existing options remain compatible.
