# Plan — CLI OpenOCD debug 3333/6666

## Mục tiêu

Hoàn thiện CLI `b300-stlink debug` để chạy OpenOCD an toàn với:

- GDB server tại `127.0.0.1:3333` mặc định.
- TCL server tùy chọn tại `127.0.0.1:6666`.
- Telnet vẫn disabled mặc định.
- TCL/Telnet tuyệt đối không được bind ra non-loopback.
- Không có lệnh erase/program/mass-erase trong debug flow.

## Kiến trúc

```text
CLI parser
  -> validate DebugConfig
  -> build_debug_command()
  -> DebugService
       -> HardwareSessionManager(DEBUGGING)
       -> OpenOCD process
       -> readiness gate: GDB [+ TCL/Telnet nếu được yêu cầu]
       -> READY
```

`DebugService` là owner duy nhất của lifecycle OpenOCD và lease ST-Link. `openocd.py` chỉ sinh argv, không tự quản lý process. Parser chỉ nhận tham số, không chứa policy phần cứng.

## Constraints / safety

1. `3333`, `6666`, `4444` phải là TCP port hợp lệ và không được trùng nhau khi cùng bật.
2. Remote bind (`0.0.0.0` hoặc IP non-loopback) chỉ cho GDB; TCL/Telnet bị từ chối trước khi launch process.
3. READY chỉ được phát khi OpenOCD log đủ tất cả listener được yêu cầu.
4. Debug flow không được chứa `erase_sector`, `program`, `mww`, `mass_erase`, Option Bytes hay WRP.
5. GDB runtime tách khỏi OpenOCD server; source/CLI có thể dùng `B300_GDB` hoặc toolchain ngoài.

## Acceptance

- Unit test parser/policy/lifecycle pass.
- `debug --gdb-port 3333 --tcl-port 6666 --dry-run --json` sinh đúng argv.
- Trên ST-Link thật: OpenOCD nhận STM32F407, listen 3333 và 6666, CLI báo READY.
- `Get-NetTCPConnection` thấy cả hai listener chỉ trên `127.0.0.1`.
- TCL RPC `version` qua 6666 trả response hợp lệ.
- Sau stop, cả 3333/6666 đóng.
- Full regression suite pass trước merge/release.
