# B300 ST-Link Tools v0.12.0 RC1 — Two-Machine Test

## Scope

RC1 is a pre-release for physical two-laptop acceptance. It does not replace the stable/latest release until field acceptance is complete.

## Machine A — Gateway

1. Install the v0.12.0 RC1 GUI package.
2. Connect STM32 + ST-Link.
3. Open **Gateway Setup**.
4. Run **Prepare This PC as Gateway**. If OpenSSH Server is already READY, the operation is a no-op.
5. Run **Gateway Self-Test**.
6. Run **Show This Gateway Fingerprint** and copy the `SHA256:...` fingerprint.
7. Receive the Client public key and run **Authorize Client Public Key**.
8. Keep OpenOCD GDB/TCL loopback-only; only SSH TCP/22 is LAN-facing.

## Machine B — Client

1. Install the same RC1 GUI package.
2. Open **Gateway Setup**.
3. Run **Generate / Reuse Client Key**. If OpenSSH Client is missing, approve the OS-component installation.
4. Copy **only** the public key and authorize it on Machine A. Private key remains local.
5. Enter Machine A IP/hostname and the fingerprint copied from Machine A into **Strict SSH host trust**.
6. Run **Scan + Verify + Trust**. Any fingerprint mismatch must block enrollment.
7. Open **Debug → Client via SSH** and enter the Gateway host/user/port.

## Test Order

1. Realtime Live Monitor first — target must remain RUNNING; no GDB attach.
2. Disconnect/reconnect Client and repeat Live Monitor.
3. Interactive Debug separately — Halt/Continue/Where/Call Stack/Registers/Variables.
4. Stop Debug and verify target restored to RUNNING.
5. Export/test VS Code/Cortex-Debug kit through the same SSH trust/key material.
6. Test CLI Client through the same host/user.

## PASS Criteria

- Gateway preparation works on a machine with and without pre-existing OpenSSH.
- Re-running preparation does not damage an existing valid SSH configuration.
- Only TCP/22 is intended for LAN ingress; 3333/4444/6666 are not opened to LAN.
- Client private key never leaves Client.
- Gateway receives only a validated ed25519 public key.
- Host-key enrollment requires exact fingerprint match.
- Host-key conflict is blocked, not overwritten.
- Live Monitor remains non-halting and restores/retains RUNNING state.
- Interactive Debug cleans up tunnel/OpenOCD/session state on disconnect.
- GUI Client, CLI Client and VS Code/Cortex-Debug all connect over SSH using the managed identity/trust material.
